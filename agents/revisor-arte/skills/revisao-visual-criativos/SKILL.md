# Revisão Visual de Criativos

Esta skill **produz evidências**. Ela **não** atribui estrelas, **não** define status e
**não** decide se a peça é aprovada — isso é do Revisor de Criação.

## Filosofia: CRITERIOSO, não RIGOROSO

> Uma peça **não precisa ser excepcional para ser aprovada.**
> Boa, profissional e publicável já é aprovação.

O revisor não é um diretor de arte refazendo a peça. A pergunta não é *"como eu faria?"*
— é *"existe aqui um problema concreto que justifique devolver isto ao designer?"*.

Se a resposta é não, a peça passa, ainda que houvesse caminho estético diferente.

## O teste do impacto observável

Uma observação visual só vira **problema** quando existe impacto observável na
comunicação ou na qualidade. Sem impacto demonstrável, é preferência — e preferência
não devolve peça.

Para cada observação, responder internamente: **qual é o impacto?** Se não for possível
descrever o impacto em uma frase concreta, não é problema.

### A pergunta obrigatória, antes de classificar qualquer coisa como problema

> **"Este problema visual é relevante o suficiente para devolver a peça ao designer?"**

Se a resposta for **não**, ele **não** derruba a peça de ⭐⭐⭐⭐ para ⭐⭐⭐. Vira, no
máximo, observação opcional — e só se for útil.

Impacto observável **existe** e **é insuficiente para devolver** são coisas diferentes.
Um desalinhamento perceptível tem impacto; nem por isso vale reabrir arquivo, refazer
export e refazer aprovação.

### Escolha de design não é defeito

Uma escolha visual diferente da que você faria **não é** um problema. Nenhum dos itens
abaixo, **por si só**, justifica ⭐⭐⭐:

| Escolha | Como tratar |
|---|---|
| **Headline em duas ou mais cores** | Recurso de ênfase. Só vira problema se quebrar a leitura a ponto de mudar o sentido da frase |
| **Assimetria / composição não centrada** | Recurso de composição. Nunca exigir simetria "porque sim" |
| **Blocos irmãos com alturas diferentes** | Escolha de diagramação. Só vira problema se parecer erro de montagem evidente |
| **Pesos e famílias tipográficas variados** | Recurso de hierarquia. Só vira problema no excesso caótico |
| **Cores fora do "esperado"** | Sem manual de marca, não existe cor esperada |
| **Densidade de texto** | Só vira problema quando compromete a leitura de fato |
| **Espaços vazios desiguais** | Respiro é decisão de design, não erro |

Antes de apontar qualquer um desses, exija de si a frase de impacto. Não conseguindo
escrevê-la sem recorrer a "ficaria melhor se", **não é problema**.

### Não fazer perícia no modo normal

No modo normal, **não** produzir:

- valores RGB exatos amostrados de regiões da peça;
- diferenças de 1 a 2 px;
- coordenadas minuciosas de blocos;
- cálculos geométricos de centralização, área ou proporção entre elementos.

Essas medições só se justificam para **confirmar um problema real já identificado por
leitura visual** — nunca para procurar problema, e nunca para converter uma preferência
em número que a faça parecer objetiva.

> Medir não torna uma preferência em defeito. Dizer que dois blocos diferem em 94 px
> continua sendo preferência se ninguém percebe a diferença olhando a peça.

| ✅ Problema válido | ❌ Preferência disfarçada |
|---|---|
| "O contraste entre o texto cinza e o fundo bege prejudica a leitura do corpo" | "Troque o azul por `#123456`" |
| "A data está sobreposta à foto e fica ilegível" | "A margem deveria ser 64 px" |
| "O logo está esticado, com proporção alterada" | "Eu usaria uma sans-serif mais moderna" |
| "Dois blocos disputam o mesmo peso e não há ponto de entrada claro" | "A composição ficaria melhor centralizada" |
| "O texto encosta na borda e parece corte de impressão" | "Falta respiro" (sem dizer onde nem por quê) |
| "O título muda de cor no meio da frase e a segunda metade some contra o fundo" | "O título usa duas cores" (sem impacto descrito) |

## Proibido sem referência objetiva

Nunca exigir, sem briefing, manual de marca ou requisito escrito que sustente:

- margens ou espaçamentos "ideais" em pixels;
- uma fonte específica que "deveria" ser usada;
- uma cor específica que "deveria" substituir outra;
- simetria, por si só;
- CTA que ninguém pediu;
- QR Code, URL, @ ou canal de contato;
- ano em uma data;
- mudança de paleta por preferência;
- unificação de cores de uma headline por preferência.

Headline em duas cores, tipografia mista, assimetria deliberada e composição descentrada
são **recursos de design**, não defeitos. Só viram problema se houver impacto observável
— por exemplo, se a troca de cor quebrar a leitura da frase a ponto de mudar o sentido.

## O que avaliar

| Dimensão | O que observar | Quando vira problema |
|---|---|---|
| **Legibilidade** | corpo, contraste, texto sobre imagem, largura de linha | quando custa esforço para ler, ou impede a leitura |
| **Contraste** | texto/fundo, elemento/fundo | quando prejudica leitura ou apaga um elemento |
| **Hierarquia** | existe ordem de leitura clara? | quando nada se destaca, ou tudo disputa |
| **Composição** | equilíbrio, massas, respiro | quando gera desconforto visível ou parece erro |
| **Alinhamento** | consistência entre blocos | quando o desalinhamento é perceptível e parece descuido |
| **Espaçamento** | margens, entrelinhas, calhas | quando elementos colidem, encostam ou sufocam |
| **Tipografia** | famílias, pesos, entrelinha, quebras | quando há excesso caótico, ou acentos colidindo |
| **Cores / paleta** | coerência interna | quando a peça se contradiz visualmente |
| **Consistência** | mesmo tratamento para elementos irmãos | quando a variação parece acidental, não intencional |
| **Tratamento de imagem** | recorte, halo, serrilhado, distorção | quando o defeito é visível em tamanho normal |
| **Acabamento** | sobras, guias, resíduos, artefatos | sempre que visível |
| **Excesso / falta** | densidade de elementos | quando compromete a leitura ou esvazia a peça |

*Avaliação visual é estimativa, não medição. Declarar confiança Média para julgamentos
perceptivos. Não medir margens em pixels para transformar preferência em número.*

## Saída esperada

Para cada observação:

- **Classificação**: problema (com impacto) · observação opcional (sem impacto)
- **Onde** na peça
- **Impacto observável** — obrigatório para tudo que for classificado como problema
- **Evidência**: o que foi visto
- **Confiança**: Alta / Média / Baixa
- **Direção de correção** — o que resolver, não qual valor usar

Se a peça estiver visualmente resolvida, dizer isso: *"Sem problemas visuais com impacto
observável"*, apontando o que está bem executado. Confirmar o que está bom é parte do
trabalho, e é o que permite aprovar sem inventar pendência.
